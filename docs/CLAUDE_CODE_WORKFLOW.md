# Claude Code로 이 프로젝트를 어떻게 진행하려는가 (계획)

이 문서는 분석이 끝난 뒤 쓰는 회고가 아니라, **지금 시점(2026-08-21, 데이터 병합만 끝난 상태)에서
세운 계획**이다. `20차시-실습/01-washington`의 같은 이름 문서는 15개 스크립트와 모델 비교까지
전부 끝낸 뒤에 쓴 회고형 기록이라 구조만 참고했고, 내용은 이 프로젝트의 실제 진행 상황에 맞게
새로 썼다. 분석이 진행되는 대로 이 문서도 계속 갱신한다. 시간순 상세 기록은
[`worklogs/`](../worklogs/)에 있다.

## 무엇을 예측하려는가

[`problem-definition.md`](./problem-definition.md)에서 확정한 문제:

1. **내일 비가 올지 (분류)** — 오늘(t)까지의 날씨로 내일(t+1) 강수 여부를 맞춘다.
2. **온다면 얼마나 올지 (회귀)** — 비가 오는 날로 조건을 좁혀 강수량을 맞춘다.
3. **기대 강수량 (결합)** — 1번의 확률과 2번의 예측량을 곱해 하나의 기대값으로 합친다.

데이터는 `data/preprocessed/seoul_weather_merged.csv` — 서울 일별 기상 1994-01-01~2024-01-01,
10,958행, 결측 없이 매일 기록. `tempmax/tempmin/temp/humidity/precip/precipprob/precipcover/
cloudcover/sealevelpressure/windspeed/solarradiation` 등을 입력 후보로 쓴다.

**가장 중요한 제약: 입력은 항상 t시점까지의 값만 쓴다.** `precip`, `precipprob` 등 t+1일자
행의 값을 그대로 입력에 넣으면 그게 곧 정답이 누수되는 것이므로, 타깃은 `precip.shift(-1)`
같은 방식으로 다음 행에서 끌어오고, 입력 피처는 절대 같은 방식으로 앞당기지 않는다.

## 계획 단계에서 이미 정한 것 / 앞으로 진행하며 정할 것

| 지점 | 계획 단계에서 정한 것 | 진행하며 확인해야 할 것 |
|---|---|---|
| 타깃 설계 | 다음날 강수 여부(분류)→강수량(회귀)→기대값(결합) 3단계 순서로 확장 | 강수량 회귀를 "비 온 날만" 조건부로 학습할지, 전체 날을 0 포함해서 학습할지는 EDA(강수 발생 비율)를 본 뒤 결정 |
| 데이터 누수 | t+1 값을 입력에 쓰지 않는다는 원칙만 확정 | `preciptype`, `conditions`처럼 관측 시점이 애매한 범주형 컬럼은 실제로 "오늘 오전에 알 수 있는 값"인지 하나씩 점검 필요 |
| 폴더/스크립트 규칙 | `01-washington`과 동일하게 `scripts/NN_동작이름.py`, `outputs/{quality,eda,model}` 3분류, `worklogs/` 날짜별 기록을 따르기로 스캐폴딩 완료 | `CLAUDE.md`에 이 프로젝트만의 규칙(강수 데이터 특유의 것)을 채워야 함 — 아직 빈 파일 |
| 평가지표 | — | 분류는 강수 발생 비율이 한쪽으로 쏠릴 가능성이 있어(계절성) accuracy만으로 판단하지 않고 recall/precision/F1도 같이 볼 예정. 회귀는 washington처럼 시간 누수 검증(이웃 날 베끼기 베이스라인)을 같이 낼지 검토 |
| 계절 변수 | — | EDA에서 월별·계절별 강수 패턴이 뚜렷하면 month/season을 입력에 추가할지 판단 |

## 예상 스크립트 순서 (확정 아님, 진행하며 번호·내용 조정)

- `01_merge_seoul_weather.py` — 완료. 원본 15개 CSV 병합·정렬·중복 제거
- `02_data_quality_check.py` — 결측치·중복값·컬럼별 기초 통계 → `outputs/quality/`
- `03_build_next_day_target.py` — `precip.shift(-1)` 기반 타깃(강수 여부/강수량) 생성, 누수 점검
- `04~06_eda_*.py` — 강수 발생 비율, 입력 후보 변수 상관관계, 계절성 → `outputs/eda/`
- `07~09_*_rain_classifier.py` — 로지스틱회귀/랜덤포레스트/XGBoost로 강수 여부 분류 비교
- `10_precip_amount_regression.py` — 강수량 회귀 (조건부 여부는 EDA 결과로 결정)
- `11_combined_expected_precip.py` — 분류 확률 × 회귀 예측량 결합
- 이후 튜닝·모델 비교 차트는 washington의 `09~11` 패턴을 참고해 필요할 때 추가

## 재현 가능성을 지키려고 정한 것

- 분류·회귀 모델을 비교할 스크립트들은 같은 입력 변수·같은 `train_test_split`(시계열이므로
  무작위 분할이 적절한지, 날짜 기준 분할이 필요한지부터 EDA 이후 결정)을 공유하게 만든다.
- 원본 데이터(`data/raw/`, `data/preprocessed/`)는 어떤 스크립트도 고치지 않고 읽기만 한다.
- 표 형식 결과는 CSV로 저장해 값 비교·diff가 쉽게 한다.
